# Accessibility (a11y) & Keyboard Navigation

HRIS applications are heavily used by Data Entry or Admin personnel who rely extensively on **Keyboard** navigation. The UI must not only be visually appealing but also fully functional without a mouse.

## 1. Basic Interactivity (Tabbing)

<CRITICAL_RULES>
- All interactive elements (buttons, links, inputs) must be accessible using the `Tab` key.
- Custom interactive components (e.g., clickable custom Datatable rows or Custom Dropdowns) must be given a `tabindex="0"` attribute if they do not use native interactive tags like `<button>` or `<a>`.
</CRITICAL_RULES>

### ✅ Correct

```svelte
<div
  role="button"
  tabindex="0"
  onclick={handleAction}
  onkeydown={(e) => (e.key === 'Enter' || e.key === ' ') && handleAction()}
>
  Custom Button Element
</div>
```

## 2. ARIA Labels

- Use `aria-label` for any button that contains only an icon (without descriptive text).

### ✅ Correct

```svelte
<button aria-label="Close modal" onclick={closeModal}>
  <Icon icon="lucide:x" />
</button>
```

## 3. Focus Trapping in Dialogs

- When a Modal/Dialog/Drawer is open, `Tab` navigation must not "leak" (escape) from the modal to the background elements.
- Initial _Focus_ must automatically be directed to the first input within that modal.

## 4. Semantic HTML & Identifier (Sectioning)

Do not use `<div>` as the primary wrapper if the element has structural meaning. Use Semantic HTML so the application structure is easier to read, maintain, accessible by screen readers (ARIA Landmarks), and to facilitate Testing and AI Vibe Coding.

<CRITICAL_RULES>
- Use `<main>` to wrap the primary content of a page.
- Use `<section>` to separate major parts (modules/blocks) within a page that are independent (e.g., data table section, filter form section, detailed information section).
- **MANDATORY `id` INCLUSION**: Every `<section>`, `<main>`, or `<aside>` **must** have a descriptive `id` attribute (e.g., `id="filter-section"`, `id="employee-table-section"`). 
  - **Purpose of `id`**: Highly useful for `aria-labelledby` references, simplifies writing End-to-End Tests (Cypress/Playwright), and is extremely helpful when providing instructions to AI / Vibe Coding (e.g., "please fix the UI in `#filter-section`").
- Use `<nav>` for navigation elements (such as Sidebar, Navbar, Tabs).
- Use `<aside>` for complementary content like a filter sidebar or secondary information.
- Use `<header>` and `<footer>` semantically within card components or the main layout.
</CRITICAL_RULES>

### ✅ Correct (Semantic & Identified)

```svelte
<main id="job-title-page" class="page-container">
  <header id="page-header" class="page-header">
    <h1 id="page-title">Job Titles</h1>
  </header>

  <!-- Filter Section -->
  <section id="filter-section" aria-labelledby="page-title" class="filter-section">
    <!-- filter form -->
  </section>

  <!-- Data Table Section -->
  <section id="data-section" aria-label="Job Title Data Table" class="data-section">
    <Datatable />
  </section>
</main>
```

### ❌ Incorrect (Div Soup & No ID)

```svelte
<div class="page-container">
  <div class="page-header">
    <h1>Job Titles</h1>
  </div>

  <div class="filter-section">
    <!-- filter form -->
  </div>

  <div class="data-section">
    <Datatable />
  </div>
</div>
```
